# Bias early, gate silence, constrain every edit

The biggest gains available to this archive do not come from swapping Whisper for a newer model. They come from fixing how ASR is run. The current `transcribe.sh` calls the reference `whisper` CLI once per file with no prompt, no voice-activity gate and default decoding. It then hands whole transcripts to a zero-shot Llama, and the research literature says that setup is more likely to hurt accuracy than help it. As of November 2026, several open-weight models measurably beat Whisper `turbo`. On the 6 November 2026 Hugging Face Open ASR Leaderboard, NVIDIA Nemotron‑3.5‑Transcribe and Qwen3‑ASR‑1.7B reach about 6.1% average short-form WER against 8.75% for turbo. On long-form audio the gap shrinks to roughly 2 points, and one 2026 study finds speech-LLM ASR *trailing* Whisper on spontaneous speech. Only a small hand-corrected gold set from this archive can settle which model wins. The user's premise that "Whisper has no context" is half right. Whisper accepts a prompt of about 223 tokens, and faster-whisper can repeat it on every 30-second window, but the current script passes none. The stronger context mechanisms are elsewhere: NVIDIA NeMo's GPU phrase boosting tolerates thousands of terms, while LLM-style ASR (Qwen3‑ASR, Nemotron) works well only with short, per-talk lists. Compute is not the constraint. A rented GH200 transcribes the whole ~6,500-hour archive for roughly $17–$250 depending on the model, the local RTX 3070 Ti can do it in days with batched inference, and the best hosted APIs cost about $1,400–$1,800. The recommended path keeps Whisper as a prompted baseline, adds VAD gating, builds a glossary and a stratified gold set, and runs a bake-off with Parakeet‑TDT plus NeMo boosting, Qwen3‑ASR and Nemotron‑3.5. It replaces whole-text LLM rewriting with deterministic paragraphing and glossary-constrained, edit-list corrections.

## The current script wastes Whisper's own context and silence controls

The repository's `transcriber/transcribe.sh` runs `whisper "$FILE" --model turbo --output_format all --language en` in a bash loop. That reloads the model for every file and uses the reference implementation's defaults. Those defaults matter for this audio. Whisper's prompt is not an instruction. It is text inserted as fake "previous transcript" after a `<|startofprev|>` token, and only the last **223 tokens** survive. In the reference CLI, `initial_prompt` applies only to the first 30-second window ([openai/whisper decoding.py](https://raw.githubusercontent.com/openai/whisper/main/whisper/decoding.py); [transcribe.py](https://raw.githubusercontent.com/openai/whisper/main/whisper/transcribe.py)). A newer `carry_initial_prompt` option re-prepends the prompt to every window. faster-whisper's `hotwords` does the same thing by a different route: it is plain text placed in the prompt slot of *every* window, and it is ignored on any window that sets `prefix` ([faster-whisper transcribe.py](https://raw.githubusercontent.com/SYSTRAN/faster-whisper/master/faster_whisper/transcribe.py)). So Whisper can be given context. It just has a small budget, and the context biases spelling. It does not command it.

OpenAI's cookbook shows that listing names in the prompt makes Whisper spell them as intended. It also shows that Whisper copies the prompt's casing and punctuation style, that sentence-style prompts beat short ones, and that the model ignores instructions written into the prompt ([OpenAI Cookbook](https://developers.openai.com/cookbook/examples/whisper_prompting_guide)). The CB‑Whisper authors report that long, list-like prompts raise hallucination, and that a prompt written to sound like a spoken transcript reduces it ([arXiv 2309.09552](https://arxiv.org/abs/2309.09552v1)). That points to a specific prompt shape for each talk. Write one or two natural, fully punctuated sentences built from the talk's metadata, for example "Dharma talk by [teacher] at [monastery] on the Heart Sutra (Maka Hannya Haramita Shingyo): zazen, dokusan, sesshin, Dogen…". Keep it to roughly 60–120 tokens so it does not crowd out the running transcript in the shared 223-token slot.

The second problem is the CLI's default `condition_on_previous_text=True`. Whisper's own docstring warns that turning it off makes the model "less prone to getting stuck in a failure loop" ([transcribe.py](https://raw.githubusercontent.com/openai/whisper/main/whisper/transcribe.py)). This archive is full of the inputs that trigger such loops. Barański et al. found Whisper produced text for **40.3% of non-speech inputs**, with hallucination rising past 30 seconds, and built a "Bag of Hallucinations" phrase list for post-filtering ([arXiv 2501.11378](https://arxiv.org/abs/2501.11378)). Calm‑Whisper traced most non-speech hallucination to a few decoder attention heads ([arXiv 2505.12969](https://arxiv.org/html/2505.12969v1)). Long zazen silences, bells and chanting are therefore the riskiest stretches of every talk.

None of this requires a new model. Swapping the CLI for faster-whisper's `BatchedInferencePipeline` gives Silero VAD on by default, batching, and a single long-lived process. On the user's exact GPU, an RTX 3070 Ti 8 GB, the faster-whisper README benchmarks large-v2 at **2m23s for a 13-minute clip with openai/whisper versus 17s batched in fp16** (about 5.5× vs 46× real time) at 6.1 GB VRAM ([faster-whisper README](https://github.com/SYSTRAN/faster-whisper)). Combine that with a carried per-talk prompt, `condition_on_previous_text=False` and word timestamps, and the baseline improves before any model swap. One caveat: whether `hotwords` and `initial_prompt` behave identically in batched mode was not confirmed, so check this in the bake-off.

The LLM stage has a separate issue in the repository that is worth checking. `llm/Modelfile-llama8-cleanup-v6a` asks Llama 3.1 8B only to insert paragraph breaks while preserving every word, but it sets `num_ctx 4800`. A 30–90-minute talk is several thousand to well over ten thousand tokens. Unless `batch_cleanup.py` chunks upstream, Ollama will not see the full transcript in context. That is a plausible contributor to the dropped and drifted text the similarity gate has been rejecting. This is an inference from the repo, not a measured result.

Older vendor claims therefore do not line up with current figures. Three readings follow from the table. First, the gain from turbo to the best open model is about **2.6 WER points on short-form but only about 2.3 on long-form**. On long-form, turbo already edges out Parakeet‑v2 and Canary‑Qwen, so the long-form *pipeline* (VAD, chunking, decoding settings) may matter as much as the model. Second, Qwen3‑ASR‑1.7B ranks fourth overall on private held-out data, just behind three commercial APIs. The leaderboard added that tab specifically to detect benchmark overfitting, so its public ranking looks genuine ([HF Open ASR Leaderboard](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard)). Third, there is a real conflict for this use case. Huber & Waibel (August 2026) found that, without biasing, Whisper large-v2 beat Qwen3‑ASR, Qwen3‑Omni and VibeVoice‑ASR on non-read speech. On Earnings‑21 the scores were 13.52 vs 14.51 / 22.57 / 16.71, and on YouTube Yodas 5.79 vs 6.69 / 7.97 / 9.63. The authors concluded that speech LLMs "do not generalize as well as Whisper on non-read speech" ([arXiv 2608.05759](https://arxiv.org/pdf/2608.05759)). Dharma talks are spontaneous, non-read speech, so the leaderboard ranking cannot be trusted blindly here.

Nothing on any leaderboard resembles cassette-era hiss, a meditation hall's acoustics or Sino-Japanese chant. URGENT24 and CORAAL are the closest proxies, and on both, Cohere, Qwen3‑ASR, Granite 5.0 and Nemotron beat Whisper by roughly 3–4 points. Hallucination profiles differ by architecture. Whisper's free-running decoder is worst. CTC and transducer models (Parakeet, Granite TurboCTC) emit per-frame labels and are widely reported to stay silent on non-speech, but that claim rests on practitioner blogs rather than a head-to-head benchmark ([ModelsLab blog](https://modelslab.com/blog/audio-generation/parakeet-cpp-vs-whisper-self-hosted-asr-comparison-2026)). LLM-decoder ASR sits in between. Canary‑Qwen's own card reports **138 hallucinated characters per minute on MUSAN non-speech** ([Canary‑Qwen card](https://huggingface.co/nvidia/canary-qwen-2.5b)). Nemotron‑3.5 trained on no-speech abstention data but still lists "repetitions, hallucinated speech" as known errors ([Nemotron card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Transcribe-30B-A4B)). Every candidate except Parakeet with local attention, Nemotron and VibeVoice needs VAD segmentation to handle a 90-minute talk anyway, and that same VAD pass is the main hallucination defence.

## Short per-talk term lists beat giant glossaries everywhere except NeMo

The archive's hard words fall into three groups: romanized Japanese (dokusan, sesshin, Shōbōgenzō), Sanskrit and Pali (Avalokiteshvara, prajñā), and lineage names. Most of them barely exist in ASR training data. The mechanisms for injecting them differ sharply in how well they tolerate long lists.

| Mechanism | Where | List tolerance | Evidence | Main risk |
|---|---|---|---|---|
| Whisper `initial_prompt` + `carry_initial_prompt` / faster-whisper `hotwords` | Local, any GPU | ~223 tokens shared with running context | Qualitative cookbook gains; no controlled long-form measurement found | Prompt words inserted into silence; loops |
| NeMo GPU‑PB ("TurboBias") shallow fusion | Parakeet (CTC/TDT), Canary AED | **Up to ~20K phrases** without slowdown; per-utterance lists | Paper claims SOTA open biasing; docs give no numeric gains | Over-boosting; `boosting_tree_alpha` must be tuned |
| NeMo CTC‑WS word spotter | CTC heads | Explicit alternative spellings (`dokusan_doku san`) | Docs only | Mapping common English words causes false hits |
| NeMo NGPU‑LM n-gram fusion | Parakeet/Canary | Trained on your own text | "Recommended for production" in NeMo docs | Needs a clean text corpus |
| Speech-LLM system prompt | Qwen3‑ASR, Nemotron‑3.5, VibeVoice | Good with ≤~10 relevant terms; **degrades 39–570% relative at 250 distractors** | Huber & Waibel 2026 | Word-order sensitivity; false insertions |
| Trained biasing module on frozen Whisper | Research code | Robust to 250 distractors (+2–17% relative) | BWER −37% to −88% relative | Not packaged |
| Hosted keyterms | AssemblyAI (1,000), ElevenLabs (1,000), Deepgram (~500 tokens), OpenAI `keywords`, Speechmatics `sounds_like` | Varies | Vendor docs | Data leaves premises; add-on fees |

Sources: [NeMo Word Boosting docs](https://docs.nvidia.com/nemo/speech/latest/asr/asr_customization/word_boosting.html); [TurboBias, arXiv 2508.07014](https://arxiv.org/abs/2508.07014v2); [Huber & Waibel, arXiv 2608.05759](https://arxiv.org/pdf/2608.05759); [OpenAI STT guide](https://developers.openai.com/api/docs/guides/speech-to-text); [AssemblyAI](https://www.assemblyai.com/blog/universal-3-pro-prompt-engineering); [ElevenLabs](https://elevenlabs.io/docs/overview/capabilities/speech-to-text); [Deepgram](https://deepgram.com/learn/deepgram-expands-nova-3-with-10-new-languages-and-multilingual-keyterm-prompting).

The most decision-relevant evidence is Huber & Waibel's 2026 comparison. When the bias list contained only the correct words, speech LLMs achieved the best biased-word error rates; VibeVoice reached 4.17% on Yodas, for example. Adding **250 distractor terms collapsed them**: Qwen3‑ASR's Yodas BWER rose from 24.52% to 48.32%, and VibeVoice's from 4.17% to 27.92%. A dedicated biasing module on Whisper barely moved, from 5.73% to 6.69%. Filtering the list per utterance first, by asking an audio model "is this word present?", recovered much of the loss ([arXiv 2608.05759](https://arxiv.org/pdf/2608.05759)). Qwen3‑ASR's technical report confirms the model was trained to treat system-prompt text as background knowledge, but it publishes no biasing numbers ([Qwen3‑ASR report](https://arxiv.org/html/2601.21337)). OpenAI's own guidance on `gpt-transcribe` warns that keywords "are hints, not required output" and should be checked for "unspoken terms" appearing ([OpenAI STT guide](https://developers.openai.com/api/docs/guides/speech-to-text)).

NeMo is the exception. GPU‑PB works at decode time on Parakeet and Canary with no retraining, scales to about 20K phrases, and supports per-utterance phrase lists for TDT greedy decoding. It ships a key-phrase F-score script for evaluation. Phrases must be pre-capitalized for models that output case, such as parakeet‑tdt‑0.6b‑v2 ([NeMo docs](https://docs.nvidia.com/nemo/speech/latest/asr/asr_customization/word_boosting.html)). Pair it with an n-gram LM trained on the archive's existing cleaned transcripts, which captures the teacher's recurring phrasing, and this is the most mature open, local way to make an ASR model "know" the domain from the start. One limitation is acoustic: boosting can only promote tokens the acoustic model already finds plausible. Expect clear wins on short, English-sounding loans like *koan* or *zazen*, and smaller ones on long Sanskrit compounds. Of all the mechanisms found, only Speechmatics `sounds_like` and NeMo CTC‑WS alternative spellings let you encode an anglicized pronunciation.

The practical rule follows from this. Do not paste a 500-term glossary into any prompt-based system. Build each talk's list from three parts: a core of 20–40 high-frequency Zen terms, the names and terms in that talk's title and metadata, and glossary terms found by phonetically matching a first-pass transcript. That last step is a cheap version of the paper's filtering stage. Feed the full glossary only to NeMo's boosting tree. Chanting is a separate case. No biasing method will reliably transcribe Sino-Japanese liturgy, so detect those regions and label them, or substitute the known liturgical text, rather than biasing toward them.

## For a monologue archive, teacher identification matters more than DER

Most talks have one dominant voice, plus sometimes an introducer, Q&A questioners and group chanting. The real goal is "teacher versus everyone else", and the open tooling handles that well.

The only independent multi-system benchmark ranks pyannoteAI Precision‑2 first at 11.2% DER and DiariZen second at 13.3%. It also found missed speech at segment edges (about 350 ms on average) to be the dominant error type, and Sortformer to be the fastest system ([arXiv 2509.26177](https://arxiv.org/html/2509.26177v1)). For a fully local, licence-clean pipeline, the realistic choices are Nemotron‑3‑Diarization or Sortformer on the GPU, which process the whole archive in single-digit GPU-hours, or community‑1, which needs either pinning pyannote.audio 3.3.x or running on rented VRAM. DiariZen is more accurate than community‑1, but its non-commercial weights need a judgment call even for a non-profit sangha. WhisperX already wires community‑1 into word-level speaker assignment, while noting that "diarization is far from perfect" and overlap is handled poorly ([WhisperX](https://github.com/m-bain/whisperX)).

Identification is the step that turns clusters into names. Enroll each teacher from several clean clips, ideally spanning cassette and digital eras. Label any diarized cluster above a cosine-similarity threshold as that teacher, and everything else as "Other". This works with any open embedding model, all of which reach 0.45–0.73% EER on VoxCeleb. pyannoteAI sells the same feature as hosted "voiceprints", but only with Precision‑2 ([pyannoteAI docs](https://docs.pyannote.ai/tutorials/identification-with-voiceprints)). The talk metadata already names the speaker, which gives free weak labels for building centroids. Chanting is the known failure mode: sung speech clusters apart from the same person's speaking voice ([Mehrabani & Hansen 2013](https://personal.utdallas.edu/~jxh052100/Publications/JP-90-SpeechComm-Mehrabani-Hansen-SigningSpeakerCluster-Mar2013.pdf)). A chant and bell detector should mask those regions before both diarization and ASR. Attach speaker labels *before* any LLM stage, and require that stage to preserve them.

The GH200 is the cheapest Hopper option on paper, but its Grace CPU is **ARM64**, which breaks the Whisper fast path. CTranslate2, and therefore faster-whisper and WhisperX, ships no official CUDA aarch64 wheel. One user's ARM64 container silently installed a CPU-only build ([speaches issue #620](https://github.com/speaches-ai/speaches/issues/620)). PyTorch 2.11 now publishes CUDA aarch64 wheels and vLLM improved its ARM support ([PyTorch KR](https://pytorch.kr/blog/2026/vllm-and-pytorch-improve-aarch64-experience/)), so NeMo (Parakeet, Nemotron), HF transformers and vLLM (Qwen3‑ASR) are the GH200-friendly stacks. TEN VAD has no aarch64 build at all ([TEN VAD](https://github.com/TEN-framework/ten-vad)). Whether NVIDIA's NIM and Riva containers publish ARM images was not verified. The practical rule: use the x86 H100 PCIe for faster-whisper or WhisperX, and the GH200 for PyTorch-native stacks. The GH200's 64 vCPUs also help, because at Parakeet speeds mp3 decoding and VAD on the CPU, not the GPU, become the bottleneck.

ElevenLabs Scribe v2 is the only system that clearly beats every open model on long-form audio (8.45 vs 10.52). Running it on a 5-hour gold set costs about a dollar and shows how far the local pipeline sits from the frontier. Sending the whole sangha archive to a third party raises consent and retention questions that this research did not resolve.

## Post-correction must propose edits, never rewrite the text

The literature on LLM error correction describes the project's current Llama stage almost exactly as the failure case. LLM correction helps when the model is fine-tuned on hypothesis-to-reference pairs, sees N-best lists or confidence scores, and works on short units. On HyPoradise, LoRA-tuned correction of Whisper N-best cut TED‑LIUM WER from 8.5 to 4.6, but **zero-shot LLaMA‑13B did not improve** noisy sets and some fine-tunes made CORAAL worse ([HyPoradise, arXiv 2309.15701](https://arxiv.org/html/2309.15701v1)). Naive LLM correction of Parakeet output on TORGO **nearly doubled WER (10.83% → 20.01%)**. The same Llama 3.1 8B, given per-word confidence and LoRA tuning, held it at 10.58% ([arXiv 2509.25048](https://arxiv.org/html/2509.25048)). An unconstrained LLM pass in another study raised CER from 5.06 to 53.10 ([arXiv 2505.24347](https://arxiv.org/pdf/2505.24347)). A practitioner test found 4-bit 8B-class models "unstable, WER 40 to 100+", with about a quarter of outputs hallucinated, while plain multi-system ROVER matched Gemini ([Alpha Cephei](https://alphacephei.com/nsh/2025/03/15/generative-error-correction.html)). An Interspeech 2025 study found LLMs gave minimal improvement on Whisper output specifically ([Xu et al.](https://www.isca-archive.org/interspeech_2025/xu25g_interspeech.pdf)). The 40–60% rejection rate at the project's 90% likeness gate is consistent with all of this.

The constructive evidence points to structural constraints. At article length, asking an LLM for **JSON error-correction pairs beat direct rewriting**. On a hard set, direct rewriting made output worse (25.24 → 27.89) while JSON edits improved it (22.36) ([arXiv 2409.07790](https://arxiv.org/html/2409.07790v2)). Named-entity correction works when candidates come from phonetic retrieval against a known list. RECOVER combined multiple hypotheses, entity retrieval and constrained edits to cut entity-phrase WER by 8–46% relative with overall WER unchanged ([arXiv 2603.16411](https://arxiv.org/abs/2603.16411)). An error-aware retriever that weights historically observed misrecognitions cut WER from 23.06% to 18.83% ([arXiv 2606.24915](https://arxiv.org/abs/2606.24915)). This archive can build exactly that table. Mine the existing 6,500 raw transcripts for n-grams that sound like glossary terms but are spelled differently, and have a human accept or reject each pair.

The safe design separates concerns so that no stage holds rewrite authority over the whole text. All current ASR candidates already emit punctuation and casing. Paragraphs can come deterministically from word-timestamp pauses (a threshold of around 3 s in patent descriptions, tuned on the gold set) plus a maximum-length split ([US 12299401](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/12299401)). If an LLM is still wanted for topic-aware breaks, ask for sentence IDs where breaks go, not regenerated text, so words cannot change. For term correction, the LLM or a deterministic matcher emits `{segment_id, original_span, replacement}`. Code then accepts an edit only if four checks pass: the span exists verbatim, the replacement is a glossary term or a spelling variant of one, the phonetic distance falls under a threshold, and the segment's total edit budget is not exceeded. Low-confidence words from Whisper or Parakeet steer where edits are allowed. Double Metaphone is English-centric and may mis-encode romanized Japanese, so a G2P-based phone distance deserves testing alongside it. This turns `likeness.py` from a post-hoc filter into a guarantee that holds by construction. Every edit also becomes an auditable diff.

## A stratified gold set of 30–50 talks decides everything above

No public benchmark covers decades-old dharma recordings, so the deciding experiment is local. Statistical work on ASR comparison shows that errors correlate within a recording, which makes utterance-level confidence intervals too narrow. Resample whole talks with a blockwise bootstrap instead ([Liu et al., arXiv 1912.09508](https://arxiv.org/pdf/1912.09508)). Many short excerpts from many talks therefore beat a few full talks. A workable design is **30–50 talks × 5–10-minute excerpts** (about 3–6 audio hours, or 25–50K words), stratified by decade, recording medium and quality tier, teacher, and the presence of Q&A, chanting and bells. Add one or two full talks to test paragraphing and long-form drift, and a separate clip set of pure silence, bells and chant to measure hallucination. This sizing is an inference: no source gives a minimum. It sits well above the roughly 8K-word scale at which older work saw ±1-point confidence intervals ([Bisani & Ney](https://typeset.io/pdf/bootstrap-estimates-for-confidence-intervals-in-asr-4a0uu8tnh9.pdf)). Correcting from an ASR draft takes roughly half the ~5× real time of transcribing from scratch ([Aigent](https://medium.com/aigent/using-automated-speech-recognition-to-support-human-transcriptions-39c6b0ae7b76)). That implies about 2–3 human hours per audio hour, or one to three part-time person-weeks, and a practitioner who knows the vocabulary matters more than typing speed. Double-transcribe 10–20% of the set to measure human disagreement. System differences smaller than that disagreement are noise.

| Metric | Measures | Tooling |
|---|---|---|
| Normalized WER/CER | Overall accuracy | Whisper `EnglishTextNormalizer` + jiwer (fold diacritics and glossary spelling variants first) |
| B‑WER / U‑WER | Whether biasing fixes glossary terms without harming other words | Custom code over alignment; NeMo key-phrase F-score |
| Glossary false-insertion rate in non-speech | Over-biasing | Custom count per hour of silence, bells and chant clips |
| Non-speech hallucination rate | Share of non-speech clips yielding text | Calm‑Whisper definition + Bag-of-Hallucinations list |
| Punctuation error rate, paragraph-break F1 | Readability | NeMo `use_punct_er`; LibriSpeech‑PC definition |
| Edit precision of the correction stage | Fraction of LLM/matcher edits that move text toward gold | Custom, reference-aligned |
| DER / WDER / cpWER | Speaker attribution on Q&A talks | MeetEval (`pip install meeteval`) |

Sources: [Whisper normalizer](https://github.com/openai/whisper/blob/main/whisper/normalizers/english.py); [jiwer](https://github.com/jitsi/jiwer); [B‑WER definition, arXiv 2401.08835](https://arxiv.org/pdf/2401.08835); [NeMo eval script](https://raw.githubusercontent.com/NVIDIA/NeMo/main/examples/asr/speech_to_text_eval.py); [LibriSpeech‑PC, arXiv 2310.02943](https://arxiv.org/abs/2310.02943); [Calm‑Whisper](https://arxiv.org/pdf/2505.12969); [MeetEval](https://github.com/fgnt/meeteval).

The transcription guidelines must state up front whether references are verbatim or clean, because Whisper's normalizer strips fillers and bracketed text. They must also fix one spelling convention for each term (Dōgen or Dogen), because the normalizer strips diacritics.

## The recommended path runs in three phases with a bake-off in the middle

The architecture below favours local, open-weight components, keeps each stage's lineage in the existing `transcript_*` JSON fields, and leaves the final model choice to the gold set rather than to leaderboards.

| Stage | Component (default) | Runs on | Notes |
|---|---|---|---|
| 0. Decode + manifest | ffmpeg/PyAV → 16 kHz mono; SQLite manifest; atomic writes; params sidecar | CPU pool | Resumable; sync off-instance on Lambda |
| 1. Non-speech gating | Silero VAD (padding ≥200–400 ms) + chant/bell tagger | CPU/GPU | Masks feed ASR, diarization and hallucination filter |
| 2. Per-talk context | Title/teacher/date + 20–40 core terms + phonetically detected terms | CPU | Full glossary only for NeMo boosting |
| 3. ASR (bake-off finalists) | (a) faster-whisper turbo/large-v3, carried prompt, `condition_on_previous_text=False`; (b) Parakeet‑TDT + GPU‑PB (+ NGPU‑LM); (c) Qwen3‑ASR‑1.7B with short context on ≤20-min VAD chunks; (d) Nemotron‑3.5 with "Context terms" | (a)–(c) 3070 Ti; (d) H100 | Hosted Scribe v2 on gold set only, as a ceiling |
| 4. Diarization + ID | Nemotron‑3‑Diarization or Sortformer v2; TitaNet/WeSpeaker teacher centroids | GPU | community‑1 only on ≥12 GB VRAM or pinned 3.3.x |
| 5. Structure | Pause-based paragraphs from word timestamps; optional LLM returning break indices only | CPU / Ollama | Words cannot change |
| 6. Constrained correction | Misrecognition table + phonetic matcher; LLM emits JSON edits on low-confidence spans; code validates | Ollama 8B | Optional ROVER across two ASR systems flags disagreements |
| 7. Evaluate + gate | Gold-set metrics per stage; hallucination/BoH filter; likeness as a sanity check | CPU | Reject by metric, not by similarity alone |

Phase one is a week of plumbing that pays off whatever happens next. Replace `transcribe.sh` with a single Python process running faster-whisper batched turbo, with VAD, per-talk carried prompts and word timestamps, on the 3070 Ti. That cuts the run from weeks to days and should visibly reduce loops over silence. In parallel, build the glossary from metadata, reference dictionaries and mined misrecognitions. The Digital Dictionary of Buddhism restricts full use by contribution level, so check its terms ([NIHU guide](https://guides2.nihu.jp/index.php/resources/431)). Start the gold set at the same time.

Phase two is the bake-off. Run the four finalists on the gold set, at a total cost of a few dollars of H100 time for Nemotron. Score them with the metric table and pick by talk-level bootstrap. Without data, the prior favours **Parakeet‑TDT‑0.6B with per-talk GPU‑PB boosting** as the bulk engine. It runs on the 3070 Ti, holds a 90-minute talk in one pass with local attention, has the most mature list-tolerant biasing, and is structurally least prone to inventing text. Nemotron‑3.5 is the accuracy challenger if roughly $150–$300 of rented H100 time is acceptable and its OpenMDW licence passes review. Whisper large-v3 with prompts remains the fallback and a second system for disagreement flagging.

Phase three is production. Run the winner archive-wide, then diarize, identify teachers, paragraph deterministically and apply only validated glossary edits. Retire whole-transcript Llama rewriting altogether.

## Conclusion

The research shifts the problem from model shopping to failure containment. Every leaderboard improvement since Whisper is worth only 2–3 WER points, and that edge partly reverses on spontaneous speech. By contrast, the archive's distinctive failure modes are within the pipeline's control: hallucinated text over silence and chant, lost or misspelled lineage terms, and LLM drift. VAD gating, short per-talk context, decode-time boosting and edit-list correction all attack them directly. That also means the existing Llama work is not wasted. Its accepted outputs, diffed against raw Whisper, become a seed list of candidate misrecognitions once a human verifies them.

The most important uncertainty is how well each model handles this archive's spontaneous, multi-era speech, and no public number answers that. The gold set is therefore the one non-negotiable investment. It turns every later choice into a measurement: model, biasing strength, whether the LLM stage stays, and whether a $1,400 API pass is worth it. Its glossary and misrecognition table can also feed a future LoRA fine-tune of the chosen model on verified talks. Use a low alpha-to-rank ratio, since alpha = 2r caused decoder hallucinations in one Whisper study ([arXiv 2606.07608](https://arxiv.org/html/2606.07608v1)).
